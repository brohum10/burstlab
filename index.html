HOW IT WORKS

A fairer comparison starts with the same workload.

The simulator creates ticket arrivals, priorities, and service times once per trial. A min-heap processes arrivals and completions; another chooses the next waiting ticket by policy. Agents finish their current ticket before choosing another.

Read the event loop ↗
  1. 01
    Generate a burst

    Fixed-seed arrivals over four hours, with a 60-minute peak window.

  2. 02
    Replay both policies

    Same tickets and service times; only dispatch order changes.

  3. 03
    Keep the trade-off visible

    Urgent misses, routine waits, backlog, and drain time are all reported.

  4. 04
    Repeat and inspect

    Thirty paired synthetic trials, bootstrap ranges, source code, tests, and saved evidence.

Read this before using the numbers.

This is an educational capacity rehearsal, not a staffing recommendation or a forecast. Arrivals and service times are generated, agents are interchangeable, work is not preempted, the waiting room is unlimited, and the model omits breaks, shifts, skills, outages, and customer behavior. Test assumptions with real data before acting.
